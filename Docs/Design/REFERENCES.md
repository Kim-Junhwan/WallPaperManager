# Design References

Reference applications are used to communicate expected product maturity,
desktop information density, and interaction quality.

They are NOT templates to copy.

---

## Fork for macOS

Use Fork as a reference for:

- professional macOS workspace structure
- high but readable information density
- sidebar hierarchy
- toolbar integration
- split-view layouts
- contextual actions
- efficient use of available window space
- desktop-sized controls
- functional rather than decorative surfaces

Important lesson:

The main content area is the workspace itself.

Fork does not present its primary editor as a large decorative card inside
another content area.

Do NOT copy:

- Git-specific layout
- branding
- exact colors
- exact toolbar
- exact sidebar structure

---

## NordVPN for macOS

Use NordVPN as a reference for:

- approachable modern macOS visual language
- clear navigation hierarchy
- restrained visual styling
- balance between whitespace and information
- understandable status presentation
- polished user-facing utility design

Important lesson:

Whitespace is used to create hierarchy, but the application still feels like
functional software rather than a collection of UI components.

Do NOT copy:

- NordVPN branding
- map-centric layout
- exact colors
- exact cards
- navigation structure

---

## Reference Philosophy

When evaluating a design, ask:

"Would this look believable if it appeared as a screenshot of a real
application on someone's Mac?"

The result should not look like:

- a UI challenge
- a design-system demo
- a landing page
- a dashboard template
- an early wireframe rendered with polished components

It should look like software that has been designed, implemented, tested,
and refined over multiple releases.
